# 踩过的坑

做这个插件时真正卡住过的地方，按"现象 → 原因 → 怎么处理"记。给以后改这个插件的人看。

---

## 1. 手机上位置一直贴在窗口最右边

**现象**：手机宽度、高度都对，但水平位置停在离窗口右边 12 像素，压在右侧栏上；竖直方向是对的。

**原因**：页面里同时挂着好几个会话面板（标签页切走的那几个也没卸载，还在 DOM 里）。`document.querySelector('[data-conversation-content]')` 按文档顺序返回**第一个**，可能正好是隐藏的那个，量出来 0×0，取不到坐标就退回默认值 12。

**我当时改错了**：把取值改成"遍历全部、取面积最大的那个"。结果更糟——页面里还有一个横向占满整个窗口的容器，按面积必然选它，算出来间距是 0，手机反而更靠右。

**最终做法**：照抄 `dsh-music` 的写法，就是用 `querySelector` 取第一个，再判断宽高过不过阈值（宽 > 200、高 > 80）。

**教训**：旁边的插件已经在同一个页面里跑通了，先抄它的取法，不要自作聪明。

---

## 2. 改了代码不生效

**现象**：代码改了，页面也按 Ctrl+Shift+R 刷新了，界面还是旧的。

**原因**：插件分两半。网页半随页面刷新，**宿主半（Node 那一侧）不随页面刷新重载**。页面刷新只能拿到旧的宿主半。

**怎么确认**：往宿主半加一个临时方法，调一下——返回"没有这个方法"就说明跑的还是旧代码。

**怎么处理**：在 DSH 里把插件那一行关掉再打开。这一步没法用页面刷新代替。

---

## 3. 应用契约里没有"我正在播放"

**现象**：任务书要求"音乐正在播放时，收起手机不能卸载它"，但契约里的十项没有一个能表达"我在播"。

**处理**：两头都做。

- 契约里加 `ctx.setPlaying(真/假)`，让应用自己说。
- 手机同时保留一套探测：应用挂载期间包一层 `window.Audio`，再查容器里的 `audio`/`video` 标签，看有没有 `paused === false`。
- 两者取或。所以现有那些不认识 `setPlaying` 的应用不会坏。

**代价**：探测会改动整个页面的 `window.Audio`，卸载时还原。如果别的插件也包了这一层，还原可能盖掉它的补丁。这是已知风险，写在这里。

---

## 4. 把几十兆的包转成 base64 会爆栈

**现象**：导入大一点的包直接报错。

**原因**：`String.fromCharCode.apply(null, 整个数组)` 参数太多。

**处理**：按 32KB 一段切开转，再拼字符串。

---

## 5. 应用代码在页面里跑，需要允许动态求值

**现象**：一开始担心拿不到 `new Function`。

**结果**：DSH 这个页面允许，所以应用的 `main.js` 是用 `new Function` 直接跑的。这也意味着**没有沙箱**（见 README 的限制一节）。

**附带结论**：应用的 `require` 是我自己做的一个小函数，只放行 `react` 和 `react-dom`，别的一律抛错。

---

## 6. `react-dom` 不保证存在

音乐那个应用必须要有 `react-dom` 才能把界面挂上去，没有就是白屏。

**处理**：`ctx.reactDOM` 明确写成"可能是 `null`"，应用用之前必须判。手机这边在插件加载时试着 `require('react-dom')`，拿不到就传 `null`，不抛错。

---

## 7. 宿主接口没有任何身份校验

**事实**：`/dsh-phone/api` 不认人。任何拿到这个地址的东西都能调：

```
POST /dsh-phone/api  {"method":"storage.get","params":{"id":"music"}}
→ {"ok":true,"data":{"value":{...音乐应用的私有设置...}}}
```

同理能 `apps.uninstall` 卸掉别人的应用，能 `apps.install` 装一个新的。

**为什么现在不修**：应用和手机在同一个页面、同一个源里，做真隔离要上 iframe 或独立进程，那 `ctx.root` 这块容器就没法给了。这是本轮明确不做的（见 README）。

**留下的后果**：清单里的权限只在应用愿意走 `ctx` 时才算数。文档里不能承诺"有权限控制"。

**以后要修的话**，至少这几条是值得的，而且不依赖保密：

- 装包时拒绝 `backend` 填 `dsh-phone`（否则应用能借转发打到手机自己的接口）
- 探活接口别把带用户名的绝对路径返回给页面
- `app.call` 单独设一个请求体上限，别和装包共用 64MB

---

## 8. 私有存储的临时文件名只用了进程号

**现象**：同一时刻两次 `set` 可能互相截断。

**原因**：临时文件名是 `<id>.json.<pid>.tmp`，同一个进程两次写会撞名。

**现状**：还没修。真实使用里很难撞上（界面同一时刻只会存一次），但记在这里。

---

## 9. 深色主题没有逐项点过

**现状**：所有颜色都走 DSH 的主题变量（`--dsw-alias-*`），理论上深浅都跟着走。但"理论"不算验过——深色下的实际观感没有一个个场景看过。

**要验的话**：切深色，看桌面、装包确认框、应用窗口、空桌面提示这四处。
