# 插件迁移指南：如何制作 dsh-phone 应用

你有一个基于 DSH 的现有插件，想把它变成可以在 dsh-phone 里运行的独立应用？这篇指南会帮你梳理转换逻辑。

## 核心前提：什么样的插件可以转换

dsh-phone 应用运行在受限的 264x340 像素容器内，且通过宿主 API 进行数据存取。如果你的插件属于以下情况，则非常适合转换：

*   **轻量化工具**：功能简单，主要进行数据展示、表单填报、简单交互。
*   **非特权操作**：不需要直接操作宿主文件系统，不要求强行修改宿主界面布局。
*   **逻辑模块化**：界面的渲染逻辑可以独立于宿主环境（即不依赖全局作用域的复杂交互）。

如果插件涉及深度系统级操作（如修改 DSH 核心设置、需要绕过沙箱的特权 API），则无法在 phone 应用的受限沙箱中运行。

---

## 转换步骤

### 1. 逻辑剥离
将插件原有的界面渲染逻辑与业务逻辑解耦。应用必须将所有界面绘制在 `dsh-phone` 传入的 `ctx.root` 容器内。

### 2. 规范目录结构
创建一个新目录，构建标准的应用包结构：

```text
你的应用名/
├── manifest.json    # 必选：应用清单（声明应用ID、名称等）
├── main.js          # 必选：入口代码
└── icon.svg         # 必选：应用图标
```

### 3. 实现入口函数 (main.js)
`main.js` 必须导出一个 `mount` 函数。这是应用加载时的入口点：

```javascript
module.exports = function mount(ctx) {
  // ctx.root 是应用渲染区域，所有 DOM 元素都应 append 到此处
  const container = document.createElement('div');
  ctx.root.appendChild(container);

  // 在此处编写插件逻辑，利用 ctx.api 与宿主通信

  // 必须返回一个销毁函数，用于关闭应用时清理垃圾
  return function unmount() {
    container.remove();
    // 销毁计时器、移除全局事件监听器
  };
};
```

### 4. 替换数据存取方式
原插件中直接调用 `fs` 读写文件的代码需要重构。请通过 `ctx.storage` 或 `ctx.api` 进行数据存取。具体的通信协议与权限清单，请参考 [docs/app-contract.md](docs/app-contract.md)。

### 5. 打包应用
将文件夹内容压缩为 zip，并将后缀修改为 `.dshapp`。

### 6. 测试与验证
将生成的 `.dshapp` 文件拖入已安装 `dsh-phone` 的界面，验证以下要点：
*   图标显示正常，点击后窗口加载正确。
*   应用运行期间功能正常。
*   关闭应用后，清理函数是否成功回收资源（无内存泄漏）。
